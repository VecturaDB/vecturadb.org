Clients

We ran 14 Chroma clients, in 11 languages, with the same test against VecturaDB 1.0.0-preview.3 and against Chroma 1.5.9. In our tests each client gave the same result on the two servers, step by step: where a client fails, it fails in the same way on Chroma 1.5.9.

Disclaimer. These results are provided as is, without warranty of any kind, as stated in the Apache License 2.0. They describe what we measured on 25 October 2026: your client, its version and your setup may behave differently.

Not sure about your client? Open an issue in the VecturaDB repository, name the client and its version, and we will take a look on a best-effort basis.

What the results mean

  • Passed: all 9 steps gave the expected result.
  • Partial: the steps the client has passed; the others are not in the client.
  • Failed: at least one step gave an error. Each failure in the table happened in the same way on Chroma 1.5.9. Four of the five failing clients call the v1 API, which Chroma 1.x no longer serves.

How we tested

  • The servers: chromadb/chroma:1.5.9 and ghcr.io/vecturadb/vecturadb:1.0.0-preview.3, for linux/amd64, with the default command of the image. The image of VecturaDB was sha256:df6c4144ca9bd85910c8a224efabcf85b17ff99306c8ea4809a43bf9f9ca0eaf.
  • A new container for each client and each server, with an empty data folder, on a Docker network: the client reached the server at port 8000. No API keys, the default tenant and database.
  • Each client ran in a container of its language, with its version pinned.

The steps were the same for every client, with embeddings of two numbers given by hand, so no embedding model was involved:

  1. heartbeat;
  2. pre-flight-checks;
  3. create a collection, with the cosine space;
  4. add 3 records with documents and metadata;
  5. query with [1, 0] for 2 results, expecting r1 then r3;
  6. get by id;
  7. get with the filter {"n": {"$gte": 2}};
  8. delete one record, then count, expecting 2;
  9. delete the collection.

The one difference between the two servers is in step 2: VecturaDB adds its server block to the answer of pre-flight-checks. The clients that show the raw answer, Python, JavaScript, Dart, Ruby and both PHP clients, took it without errors, with the same max_batch_size, 5461.
